# Modernization review — 2026-10-11

Scope: every commit from `3bf4ef6e` (exclusive) to `f0021f294` (inclusive) on `main`.
116 commits, 493 files, +35.8k / -26.5k lines.

Method: read-only source and git inspection plus a rebuild of the current gates (see
"Measured baseline"). Each finding is marked **verified** (read in source or produced by a
command during this review) or **inferred** (reasoned from verified facts, not observed).
Nothing in this document changes code; it records findings and proposed improvements only.

## Verdict

The direction is sound and the work is disciplined: decisions are written down, fixed wire
widths are kept apart from native pointer width, new renderer code lives in `Core/`, and no
binaries or build outputs are committed.

Two things undercut it:

1. The project has gone five weeks without a running game. `z_generals` does not link, and the
   order of work (deep fidelity on water before any UI can draw) keeps first boot far away.
2. The validation is weaker than `PROJECT_STATE.md` and `ROADMAP.md` describe. Part of the
   Step 01 determinism guard no longer compiles into any test, the headless determinism test
   does not run game logic, and the policy tests are text searches.

Neither is a reason to change direction. Both are reasons to change the order of work.

## Measured baseline

Rebuilt at `f0021f294` on 2026-10-12, Windows 11, MinGW-w64 GCC 16.2.0, AMD Radeon RX 640.

- `ctest --preset mingw64-tests`: **31 of 32 pass.** `d3d12_backend_smoke` fails, the same way

  `Material sampler pixel failed expected 191,64,0` (`Core/Tests/D3D12BackendSmokeTest.cpp:404`,
  the trilinear mip-blend case). The state documents record 32/32.

## Findings

### 1. No running game (highest priority)

- **verified** `PROJECT_STATE.md:21,26`: the executable link fails and "Normal game link/boot,
  D3D12 creation in that executable, first visible game/UI frame ... remain unproven".
- **verified** Textured 2D is not drawn. `GeneralsMD/Code/Libraries/Source/WWVegas/WW3D2/render2d.cpp:608-665`
  submits only untextured, non-grayscale geometry under `RTS_EVOLUTION_X64` and then returns.
  UI images, fonts and video quads use this path.
- **inferred** Once the link is fixed, the first boot will show almost nothing on screen, so
  the "first visible frame" milestone is further away than the unresolved-symbol count suggests.
- **verified** Still on raw D3D8 in compiled code: scene fog, wireframe and the occluded-unit
  stencil pass (`GeneralsMD/.../W3DScene.cpp:976-1078,1255-1282`), heat smudge
  (`W3DSmudge.cpp:83-280`), snow (`W3DSnow.cpp:79-410`), dazzle (`dazzle.cpp:392,922,947`),
  status circle, in-game UI geometry, file-texture creation (`textureloader.cpp:265,448,703,2594`),
  render-to-texture in `W3DShaderManager.cpp:648-861`.
- **verified** Every ported feature (terrain, roads, water, shadows, particles, filters) is
  exercised only by `Core/Tests/D3D12BackendSmokeTest.cpp`, never by the game.
- **verified** `DX8Wrapper` is still referenced 514 times in `Core/` (26 files), 420 in
  `Generals/` and 415 in `GeneralsMD/`, while `dx8wrapper.cpp` is out of the build.

### 2. Determinism guard is thinner than documented

- **verified** `Core/Tests/DeterminismPrimitivesTest.cpp:99-334,504-516` (Xfer bytes, XferCRC
  folding, `DamageInfoOutput` snapshot order, replay/network ABI widths) is behind
  `RTS_ENGINE_DETERMINISM_TEST`. No CMake file defines that macro; it was removed in
  `5cfef819d`. Only the CRC, RNG and fast-float vectors run.
- **verified** That dead block could not pass on x64 as written (it expects
  `sizeof(void*) == 4` and `sizeof(GameMessage) == 36`), so it needs porting, not just
  re-enabling.
- **verified** Test-only seams (`RTS_STANDALONE_DETERMINISM_TEST`) remain in production
  `Xfer.cpp`, `XferCRC.cpp` and `Damage.cpp` with no test using the Xfer ones.
- **verified** `Core/Tests/HeadlessDeterminismTest.cpp:17-95` is a six-field simulation driven
  by the RNG. It does not run `GameLogic`.
- **verified** Two tests can regenerate their own fixtures (`HeadlessDeterminismTest.cpp:225`
  `--emit`, `EvolutionFullSessionTest.cpp:537` `--emit-fixture`).
- **inferred** The goldens come from this project's own MinGW build, not from a retail binary
  (`History/STEP_01_DETERMINISM_GUARD.md:158-162` says expected values "were updated to match").
- **verified** No test opens a `.rep` file. `GeneralsReplays` is referenced only by
  `.github/workflows/check-replays.yml`, which needs the VC6 build.
- **inferred** Replay parity with retail on x64 is unproven. `FPUControl.cpp:28-38` uses SSE
  round-to-nearest where x86 used x87 `_PC_24`.
- **verified** The 12 policy tests in `cmake/tests/` (1,674 lines) are substring searches over
  named source paths (`PolicyTestHelpers.cmake:16-41`). They catch a retired name coming back;
  they do not test behaviour, and they break when a file moves.
- **verified** `PROJECT_STATE.md` cites `build/*.txt` and `build/*.json` receipts. `build/` is
  untracked (`.gitignore:11`) and most cited files are not on disk.

### 3. D3D12 backend is prototype-grade

All in `Core/Libraries/Source/WWVegas/WW3D2/Backend/D3D12Backend.cpp` unless noted.

- **verified** Two `CreateCommittedResource` upload buffers per dynamic draw (`:1633-1640`).
  Meshes, particles, decals, shadow volumes and 2D all use this path.
- **verified** A blocking GPU wait, with a fresh allocator and command list, on every
  static-geometry create (`:1925-1936`) and texture create (`:2222-2233`); also in
  `Copy_Texture` (`:1271-1293`) and on release outside a scene (`:2065`, `:2754`).
- **verified** `meshrenderer.cpp:300-391` transforms, lights and UV-maps every vertex on the
  CPU each frame, de-indexed to three vertices per triangle. `Set_Ambient` and
  `Set_Light_Environment` are no-ops (`:2763-2774`).
- **inferred** The three items above are the largest performance risk; the project's stated
  goal is removing CPU work, and this path adds it for meshes.
- **verified** No debug layer: no `D3D12GetDebugInterface` or `ID3D12InfoQueue` in the backend
  or its tests. Validation errors are therefore invisible.
- **verified** No `ComPtr`; raw pointers with manual `releaseCom`.
- **verified** `GetDeviceRemovedReason` is read in one place (`:1316`); there is no recovery.
- **verified** `Present` and `Begin_Scene` failures throw `std::runtime_error` (`:2838`,
  `:945-947`). **inferred** `ww3d.cpp:826,1068,1111` do not catch, so a lost device ends the
  process.
- **verified** Shaders compile from `Shaders\PrimitiveColor.hlsl` at every startup
  (`:209-245`, nine entry points). Compile errors go to `OutputDebugStringA` only.
  **inferred** There is no `install()` rule for the `.hlsl`, so an installed build would fail
  renderer init.
- **verified** Pipeline states are created lazily inside the draw path on a cache miss
  (`:2475`), found by linear search, keyed partly by raw `depth_bias`.
- **verified** No resource-state tracking; before/after states are hard-coded.
- **verified** 16-bit indices only; RGBA8 and RG8_SNORM textures only (`:2084-2090`), DXT
  decoded on the CPU; `Set_Gamma` is a no-op (`:920-927`); no fullscreen path; software
  adapters rejected, so the GPU test needs real hardware.
- **verified** One `VSTerrain` / `PSTerrainTexture` pair serves terrain, flat water, river and
  sea through mode flags in `RenderBackendTerrainState` (`IRenderBackend.h:227-252`), checked
  by a 75-line validator (`:2532-2609`).
- **verified** `meshrenderer.cpp` skips the draw and prints to `stderr` for second texture
  stages (`:310`), NPatch (`:166`), unsupported material shaders (`:318`), depth cue/specular
  (`:332`) and texture-coordinate mappers (`:347`).

## What is good and should be kept

- Fixed-width wire, replay and Xfer fields are separated from native pointer width, with tests
  (`ArchitectureAbiTest`, `WireAbiTest`, `RuntimeNativeWidthTest`).
- `CommandPacket` capacity no longer depends on `sizeof(GameMessage)`
  (`NetworkDefs.h:95-106`).
- The Evolution codec rejects unknown versions and malformed input, with golden bytes.
- Integer item data in GUI gadgets has its own typed API (`GadgetListBoxSetItemIntegerData`)
  instead of pointers cast to integers.
- All new backend code is shared in `Core/`.
- No `#pragma pack` changes; no native-width type added to a serialized struct.
- Decisions, guardrails and a roadmap exist and are followed.

## Improvements, in the order I would do them

1. **Reach a first frame before porting anything else.** Port textured `Render2D` (UI, fonts)
   and file-texture creation; make the remaining D3D8 effects (smudge, snow, dazzle, fog,
   stencil pass) compile as explicit skips. Link, boot to the main menu, then return to
   fidelity work with the game as the test bench.
2. **Turn on the D3D12 debug layer** in `D3D12BackendSmokeTest` and in debug game builds, and
   fail the test on any validation message. Every draw path so far was written without it.
3. **Revive the Xfer / XferCRC / snapshot characterization** on x64: define the macro again,
   replace the 32-bit size expectations with the fixed-width ones, and remove the test-only
   seams that stay unused.
4. **Add one real determinism gate:** play a replay from `GeneralsReplays` headless and compare
   CRC checkpoints. This is the only test that would detect an x64 float divergence.
5. **Replace per-draw upload buffers with a per-frame ring**, and batch resource creation so
   it does not wait on the GPU once per resource.
6. **Make renderer failure non-fatal:** catch at the `WW3D` boundary, log to a file, and
   surface shader compile errors there instead of `OutputDebugStringA`. Add an `install()`
   rule for the `.hlsl`, or compile shaders at build time.
7. **Rename or redefine the `RETAIL_COMPATIBLE_*` macros** so they describe what the Evolution
   build actually guarantees.
8. **Decide the fate of base Generals and the tools** and record it in `DECISIONS.md`: either
   build them on x64 in CI, or state that they are frozen. Today they rot silently.
9. **Give the fork its own CI** (one job: `mingw64-tests` + `ctest`), and remove or guard the
   presets that cannot configure.
10. **Commit validation receipts or stop citing them.** A short tracked summary per milestone
    is enough.
11. **Collapse the state documents.** Keep `PROJECT_STATE.md` as the current state only and
    move history to `WORKLOG.md`; remove the duplicated section and the stale symbol count.
12. **Split behaviour from grep in the policy tests,** and key them on symbols rather than file
    paths where possible, so upstream file moves do not break them.
13. **Smaller commits with descriptive messages.** A 6,499-line commit cannot be reviewed or
    bisected.
14. **Plan audio.** Without a Miles replacement the x64 game is silent; this needs a decision
    even if the work is later.
